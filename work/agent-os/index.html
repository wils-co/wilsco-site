The Problem

Single chats fail when running a real fleet.

Standard AI coding tools assume an interactive, single-model chat loop. When you run multiple models concurrently—frontier orchestrators for high-level judgment, resident local weights for fast iterative execution, and background cron agents—that model collapses.

Context gets lost between seats, token spend blows out on routine file operations, and background jobs leave no inspectable audit trail. You end up babysitting every prompt instead of governing an engineering pipeline.

The Architecture

Frontier brains, local muscle, durable files.

agent-os was built as the operational control surface for a Mac Studio M3 Ultra (256GB unified memory) running alongside cloud providers. It enforces a strict architectural contract:

  • Orchestrator as Judge: High-reasoning models (Claude, Grok) handle problem decomposition, specification drafting, and final pull-request judgment.
  • Local Weights as Executors: Dedicated local models (Qwen 3.8 27B on Ollama, oMLX) implement bounded unit files and run test suites directly on disk with zero metered API cost.
  • Markdown Vault as State: No proprietary vector databases or volatile agent memories. Persistent state lives in human-readable markdown files, structured handoff specs, and kanban boards.
  • Maker-Checker Reviews: The model authoring code never self-approves. Diffs are evaluated by an independent reviewer seat before merging.
Sanitized Snapshot

Inspectable code without private leaks.

The public repository is an open-source, sanitized snapshot of the watchtower runtime engine. It includes full UI templates, background task scrapers, session parsers, and synthetic fixture data for local testing.

All private telemetry, customer data, personal credentials, and live vault paths are completely stripped. You can clone the repo and launch the demo suite locally in seconds:

# Clone and run the demo suite
git clone https://github.com/wils-co/agent-os.git
cd agent-os
python3 demo.py
./start.sh
